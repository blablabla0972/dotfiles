# Test Infrastructure & Methodology Specification

## 1. Overview & Philosophy

The verification framework for this dotfiles repository is designed around **opaque-box, requirement-driven, deterministic testing** governed by the **Verification-Before-Completion** and **Ponytail** principles.

Key testing tenets:
- **Opaque-Box Verification**: Tests validate observable interfaces, standard exit codes, stdout/stderr streams, file system state transitions, and structured JSON envelopes. Implementation internals can evolve without breaking tests as long as behavioral contracts are preserved.
- **Hermetic Isolation**: Tests run in disposable temporary environments (`tempfile.TemporaryDirectory`). Explicit overrides of `$HOME`, `$XDG_CONFIG_HOME`, `$XDG_STATE_HOME`, `$XDG_CACHE_HOME`, and `$XDG_RUNTIME_DIR` guarantee zero cross-contamination with the host user environment or live desktop session.
- **Fail-Safe Compositor & Service Mocking**: Tests interacting with compositor IPC (`hyprctl`), daemon control (`systemctl`), wallpaper daemons (`swww`), or shell managers (`noctalia`) use isolated, controlled stubs. No test ever issues commands to a live display server or active desktop workspace.
- **Fast, Deterministic Execution**: All test suites execute locally in seconds via standard `pytest`, requiring no external network access or complex test containers.

## 2. Four-Tier Testing Methodology

To provide layered confidence across all levels of granularity, tests are structured into four rigorous tiers:

```
┌─────────────────────────────────────────────────────────────┐
│ Tier 4: Real-World Scenarios (End-to-End Lifecycle & Flow)  │
├─────────────────────────────────────────────────────────────┤
│ Tier 3: Cross-Feature Combinations (Inter-System Coexistence)│
├─────────────────────────────────────────────────────────────┤
│ Tier 2: Boundary & Corner Cases (Errors, Traversal, Corrupt) │
├─────────────────────────────────────────────────────────────┤
│ Tier 1: Feature Coverage (Core Functionality & CLI Flags)   │
└─────────────────────────────────────────────────────────────┘
```

### Tier 1 — Feature Coverage
Focuses on baseline functional requirements for every core utility and script:
- `install.sh`: Verification of `--dry-run` output formatting, selective component installation (`hypr`, `btop`), and symlink target resolution.
- `bin/toggle-desktop`: Single-instance locking, active workspace inspection, workspace switching to desktop workspace (10), and return toggle.
- `config/hypr/scripts/generate-theme.py`: Option parsing, `--help` contract, `--theme-mode-changed`, and `--apply-wallpaper` flags.
- `config/quickshell/wallpaper-switcher/preview-palette.py`: Palette generation, schema validation, hex swatch format verification, and cache population.

### Tier 2 — Boundary & Corner Cases
Probes resilience under abnormal, adversarial, or malformed inputs:
- **Invalid Targets & Traversal**: Supplying non-existent package names, path traversal payloads (`../etc`, `../../`), empty strings, or hidden paths (`.git`) to `install.sh`.
- **Compositor Failures**: Missing focused monitor JSON output or compositor disconnect during `bin/toggle-desktop` execution.
- **Corrupted State Recovery**: Recovery from empty, truncated, or binary-corrupted state files (`toggle-desktop.state`).
- **File System & Request Anomalies**: Non-existent image paths, malformed carousel request IDs (`bad id with spaces!`), and oversized or invalid preview cache JSON files.

### Tier 3 — Cross-Feature Combinations
Validates seamless interactions between distinct system layers:
- **Palette Consistency**: End-to-end synchronization between `preview-palette.py` swatches and Matugen outputs generated by `generate-theme.py`.
- **Backup & Snapshot Namespace Isolation**: Independent coexistence between installer configuration backups (`~/.config/backups/dotfiles-*`) and theme rollback snapshots (`~/.local/state/desktop-wallpaper/backups/`).
- **Concurrent Lock Contention**: Rapid parallel invocation of `bin/toggle-desktop` verifying `flock` serialization without race conditions or corrupted workspace state.
- **Orphan Cleanup Coexistence**: Preservation of custom user executables while pruning dead dotfiles symlinks in `~/.local/bin`.

### Tier 4 — Real-World Application Scenarios
Simulates realistic end-to-end user workflows and recovery sequences:
- **Full Installation Lifecycle**: Clean home dry-run -> live installation -> second-run idempotency check -> orphan symlink pruning.
- **Theme Transaction Rollback Resilience**: Simulated transaction aborts mid-flight verifying byte-for-byte rollback of all configuration targets.
- **Complete Carousel-to-Desktop Workflow**: User browsing wallpaper carousel previews -> selecting image -> applying transactional theme -> toggling desktop workspace to inspect wallpaper -> returning to workspace.

## 3. Test Architecture & File Organization

The test suite is organized under `tests/` and executed via `pytest`:

```
tests/
├── check_palette_matrix.py              # WCAG contrast verification runner
├── test_adaptive_tokens.py              # Token derivation & contrast math unit tests
├── test_adaptive_transaction.py         # Theme transactional rollback unit tests
├── test_carousel.py                     # Wallpaper carousel layout unit tests
├── test_installer.py                    # Core installer unit tests
├── test_matugen_cache.py                # Matugen hash caching unit tests
├── test_palette_surfaces.py             # Palette color roles unit tests
├── test_preview_cache.py                # Preview palette disk caching unit tests
├── test_rice_install.py                 # Rice installer tests
├── test_theme_safety.py                 # Immutable generator files safety tests
├── test_theme_sync.py                   # Theme synchronization unit tests
├── test_toggle_desktop.py               # Desktop toggle helper unit tests
├── test_wallpaper_helpers.py            # Wallpaper helper unit tests
│
├── test_e2e_common.py                   # Shared hermetic E2E fixtures & stubs
├── test_e2e_tier1_feature_coverage.py   # Tier 1: Core feature verification
├── test_e2e_tier2_boundary_corner.py    # Tier 2: Boundary & corner cases

└── test_e2e_tier4_real_world.py         # Tier 4: Real-world workflows
```

## 4. Feature Coverage Mapping Matrix

| Feature / Component | Tier 1 (Coverage) | Tier 2 (Boundary) | Tier 3 (Cross-Feature) | Tier 4 (Real-World) |
|---|---|---|---|---|
| `install.sh` (Installer) | Dry-run, selective target linking (`hypr`, `btop`) | Path traversal, invalid targets, empty arguments | Backup preservation alongside theme snapshots, orphan pruning | Full lifecycle: dry-run -> fresh install -> idempotent re-run -> cleanup |
| `bin/toggle-desktop` (Show Desktop) | Workspace toggle round-trip (active -> 10 -> active) | Missing monitor focus, corrupted state recovery | Rapid concurrent multi-process `flock` serialization | Complete carousel apply + desktop toggle workflow |

| `preview-palette.py` (Palette Preview) | CLI preview generation, 5-swatch format, cache hit | Corrupted cache recovery, invalid mode, missing file | Shared color semantics with `generate-theme.py` | Multi-image carousel browsing and caching cycle |

## 5. Verification Commands & Acceptance Criteria

### Running Test Suites
```bash
# Execute entire test suite (unit + E2E)
pytest tests/ -v

# Execute E2E tiers exclusively
pytest tests/test_e2e_*.py -v

# Execute individual tiers
pytest tests/test_e2e_tier1_feature_coverage.py -v
pytest tests/test_e2e_tier2_boundary_corner.py -v
pytest tests/test_e2e_tier3_cross_feature.py -v
pytest tests/test_e2e_tier4_real_world.py -v
```

### Static Syntax & Integrity Checks
```bash
# Shell script validation
bash -n install.sh wt-prep.sh bin/toggle-desktop

# Fish shell syntax validation
fish --no-execute config/fish/config.fish

# Python syntax compilation
python3 -m py_compile config/hypr/scripts/generate-theme.py \
  config/quickshell/wallpaper-switcher/preview-palette.py \
  config/rice/theme/derive_tokens.py \
  tests/*.py
```

### Acceptance Gate
- **Pass Rate**: 100% (0 failures, 0 errors, 0 skipped tests).
- **Execution Time**: Entire E2E suite executes in < 5 seconds.
- **Side Effects**: Zero residual files in host `$HOME`, `/tmp`, or `/run/user`.
